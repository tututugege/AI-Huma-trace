## 前端带宽：2-taken（取指一拍两块）与空拍来源（BPU 覆盖气泡）

**日期**：2026-11-19。**分支**：trace-model `exp/fe2t`（基于 main `8fd0ae3`；`24175b8` FE_PAIR 修复，`4307eb8` PMU 拆分，`e5db4f9` 研究开关；工作区 `trace-model-fe2t`），**未合入**。数据 `~/personal/AI-Huma-data/fe2t`（`tools/cmp_pair.py`、`tools/fe_w.py`），eda `tm/res_fe2t_{p0,p1,p17}`、`res_fe2t2_p0`、`res_fe2t3_{orc,ub8}`，二进制 `tm/bin/sim64_fe2t*`（iprc-jump `~/rv64spec/fe2t*`）。

- **问题**：当前 main 的 TMA（386 点，`res_wbp1`）前端占 31.8% 槽位，其中带宽 29.5%；前端每拍只送 0.55–0.92 个组。要不要做 2-fetch / 2-taken。
- **当前 main 的前端供给拆分**（FEO，386 点 SimPoint 加权，占前端 slot 的 %）：以 taken 结尾丢 28.8%，到 64B 行尾 8.4%，"指令 FIFO 空"空拍 14.5%，重取指 10.7%，I$ 缺失 3.5%。
- **FE_PAIR 在 rv64gc + RVC 上原来不能用**（quick-sort 等 ROB 死锁）。4 个问题，最后都表现为 JAL 在 BRU 里"误预测"——JAL 没有分支标签，错误路径杀不掉：① BPU 判"目标是顺序下一条"按 slot 算，没考虑 4 字节分支；② 第二块只有 1 个半字且是 32 位指令时整条被携带到下一组，组里没有第二块的指令、FTQ 的 next 却是第二块的出口——改为第二块至少 2 个半字；③ 第二块取不到时，第一块末尾的 32 位 `jal` 被 RVC 组尾规则截成低半字；④ S_D 撤回 pair 后按 PTAB 切块，新组尾用了原组尾的高半字。另外 `stream_cmp.sh` 依赖的 `TB_PCTRACE` 已在清理中删除，这项检查实际失效，改为比较 `TB_TRACE_COMMIT`：`FE_PAIR=0/1` 63 个 C 程序里 62 个提交流相同（memory-stress-small 在 main 上也不同，是 `FE_PAIR=0` 一侧的轨迹漏打一条 `lw`）。默认周期不变（C 门禁 68/68；`build_c` 里的 fdoff 是 `68a8e92` 之前的旧二进制，重编后 8059）。
- **结果**（8 个前端受限程序 × 权重最高 3 点 = 24 点，10M 预热 + 10M，PF 开，相对 `FE_PAIR=0`）：

|---|---|---|---|---|
| perlbench | +2.83% | +2.13% | +9.96% | +5.38% |
| gcc | +1.32% | +0.77% | +5.68% | +3.56% |

| sjeng | −0.17% | +0.82% | +18.01% | +6.37% |

  - `FE_PAIR=1` 让 taken 截断的丢槽降 15–50%、每拍送出的指令变多（xalancbmk 4.0→5.4），但 IPC 基本不变。第二块的条件分支用"第一块走完后"的推测历史查 TAGE，误预测上升（astar sp30 每千条 3.01→3.41）；`=17` 去掉这部分后 8 个程序全部为正。比 EXP-023（rv32，8 个 4 字节 slot）的 +2.9% 小得多。
- **空拍来源**：逐拍跟踪 itt-dispatch，每次 S_D 覆盖之后输出端空 2 拍，那时 BPU 已经恢复发射，原 PMU 按瞬时状态记成"指令 FIFO 空"。改为覆盖 / 预译码冲刷之后 4 拍内的空拍记到它头上（只改 PMU，24 点周期逐个相同），并加覆盖种类计数（`BPU_OVR_SD_*`、`BPU_OVR_L1`）。结果"FIFO 空"全部变成覆盖气泡：S_D + S1 覆盖占前端 slot 的 7–27%，覆盖次数是误预测的 10–40 倍（omnetpp 每千条 159 次覆盖、4.1 次误预测）。S_D 覆盖大多是"S0 的 uBTB 没有 taken、主预测器有"（uBTB 不认识这个分支），astar 方向相反的也多。重取指（前端自身重填 3 拍）在 TMA 里属于 BadSpec。
- **覆盖上界与 uBTB 容量**：`FE_OVR_ORACLE=1`（S0 直接用主预测器的结果，误预测次数不变）+7.29%。uBTB 放大 8 倍拿到约一半（+3.34%）：S_D 覆盖每千条 gcc 34→17、omnetpp 61→33，S1 覆盖大多消失；astar 的 S_D 覆盖不变（约 90，方向分歧，与容量无关）。
- **结论**：这些程序的前端损失主要是 BPU 两级覆盖的气泡（uBTB 只有 128 项，每次覆盖损失 1–2 拍），不是 taken 截断；2-taken 在当前配置下性价比低。值得做的方向：① 降低覆盖代价——覆盖后同拍发射纠正的块（EXP-023 的 `FE_BFAST`，当时 +1.2–1.8%，代价是 BPU 深度 +34%，模型代码已删），或让 S1 级的结果更早到 S0；② 降低覆盖频率——uBTB 容量与组织（8 倍容量约拿一半上界），以及 uBTB 方向计数器与 TAGE 不一致的部分（astar）；③ 行尾截断（7–14%）用越过行边界取指。
- **uBTB 优化实验**（`404661e`，同样 24 点，相对同一构建的默认配置；eda `tm/res_ub_*`）：

| 配置 | uBTB 存储 | 几何平均 | 说明 |
|---|---|---|---|
| 默认：128 项 × 93 b（目标 63 b） | 11.9 Kb | — | |
| `FE_UB_STRONG=1`（S0 计数器饱和才预测 taken） | 同 | **−1.81%** | 8 个程序全负（xalancbmk −6.4%）；S_D 覆盖几乎不变，S0 少猜的 taken 变成 S1 / S_D 覆盖，不采用 |

| 压缩 + 512 项 | 25.6 Kb | **+2.31%** | perlbench +5.9%、gobmk +3.9%、sjeng +3.6% |

  - **S_D 覆盖的种类**：`NEWTK`（S0 没有 taken）几乎全是 S0 **没有这个块的项**（gcc 23.9 次 / 千条里 23.5 次、gobmk 36.8 里 35.9），不是计数器弱；astar 例外（`NEWTK` 28.8 里只有 4.8 是缺项，主要是方向相反 31.6、槽位不同 26.8，与容量无关）。
  - **加 S0 容量主要减少的是 S1 覆盖**（256 项：perlbench 26→16、omnetpp 98→65、xalancbmk 7.3→2.3 次 / 千条），S_D 覆盖只少一点（512 项：gcc 34→31、omnetpp 61→48）：S_D 覆盖的那些块在 S1 的 512 项 uBTB 里也没有，要靠加大 S1 级（之前 S0 ×8 + S1 ×8 时 gcc S_D 34→17）。
  - **同一分支在不同块起点下重复分配**：S0 分配中 4–37% 的分支 pc 之前已在另一个块起点下分配过（xalancbmk 37%、astar 31%、sjeng 21%），按块起点索引浪费了一部分容量，但不是主因。
  - **建议**：S0 目标压缩到 20 b（零损失）、用省下的面积把 S0 加到 256 项（存储不变，+1.23%）；要更多需要同时加大 S1 级 uBTB（S_D 缺项）。astar 类的方向分歧要 S1 级带历史的方向预测，`FE_UB_STRONG` 这种只改阈值的做法不行。

- **覆盖后同拍发射（`FE_OVR_FAST`，`da73eb7`）**：覆盖发生的那一拍，S0 就按纠正后的地址发出下一块（原来要等下一拍）；位 0 = S_D 覆盖，位 1 = S1 覆盖。取指地址 FIFO 本来就是先丢被冲掉的尾部再压入，不用改。`FE_OVR_FAST=0/3` 61 个 C 程序提交流相同（memory-stress-small 是已知的轨迹问题），默认周期不变；itt-dispatch 210273 → 185594 拍（上界 165231）。24 点（eda `tm/res_of*`），相对默认：

- **没有做**：RTL（同拍发射的时序代价是关键）；全量 386 点；带历史的 S1 方向表；越过行边界取指。

## 研究开关（都只在模型里，默认关，默认周期不变）

| 开关 | 类型 | 作用 |
|---|---|---|
| `FE_PAIR` | 环境变量 | 一拍取两块（2-taken）；`17` = 条件分支结尾的块之后不配对 |
| `FE_OVR_ORACLE=1` | 环境变量 | S0 的猜测直接用主预测器的结果（覆盖零气泡上界） |
| `FE_OVR_FAST` | 环境变量 | 覆盖那一拍 S0 就按纠正后的地址发射；位 0 = S_D，位 1 = S1（注意 RTL `FE_BFAST` 的位序相反：位 0 = S1，位 1 = S_D） |
| `FE_UB_STRONG=1` | 环境变量 | S0 计数器饱和才预测条件分支 taken（结论：变慢，不用） |
| `CFG_UB_S0_N` / `CFG_UB_L1_N` / `CFG_UB_L1_W` | 编译宏 | S0 / S1 uBTB 项数、S1 路数（默认 128 / 512 / 2 = RTL） |
| `CFG_UB_TGT_BITS` / `CFG_UB1_TGT_BITS` | 编译宏 | S0 / S1 uBTB 目标只存低若干位（区域外不存）；默认完整 |

PMU（model-only）：`FEO_LOSS_OVR_SD` / `OVR_L1` / `PDFLUSH` 现在包含覆盖之后 4 拍内的空拍（以前算 `FEO_LOSS_IFIFO`），新增 `BPU_OVR_SD_{NEWTK,NOTTK,SLOT,TGT,OTHER,NEWTK_NOHIT}`、`BPU_OVR_L1`、`UB0_ALLOC`、`UB0_ALLOC_OTHER`。

## RTL 时序（进行中）

RTL 里同一机制已有：`FE_BFAST`（`bpu_ctl.sv`，默认 0），S0 查的是 `pc1` = refetch / S_D 结果 `fin.next` / L1 结果 `g1.next` 的选择（`bpu_cmd.sv`）。按已有单模块深度估计：S0 环（uBTB 查表 29 + `bpu_cmd` 24 + `bpu_spec` 91，整个 `bpu` 141 层）前面，S_D 版要再串上 `bpu_main_sel`（70）+ 比较 + 选择，约 +50%；S1 版串上 L1 查表（约 30）+ 比较，约 +25–30%。可能的降法：L1 uBTB 的读提前到 S0（与 uBTB 并行，结果打一拍进 S1），S1 同拍发射只多比较 + 选择；S_D 覆盖那一拍只把纠正后的地址送去取指，S0 查表和历史留到下一拍。`FE_BFAST` = 0 / 1 / 2 / 3 的 `bpu` 综合深度在 rtl worktree `rtl-bfast`（`build/synth_bfast*`）里跑，结果补在这里。

2-ahead（用前一块的地址和历史提前一拍查主预测器、块确定时从候选里选）能去掉覆盖本身，上界接近 +7.3%，但要整体重写 BPU（候选并行读、BTB / ITT / RAS 组织、检查点与修复），并损失一块历史的准确率；先在模型里用 `FE_OVR_ORACLE` 加"上一块的索引"估准确率损失再决定。
